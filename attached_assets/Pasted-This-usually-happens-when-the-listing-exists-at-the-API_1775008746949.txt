This usually happens when the listing exists at the API/data level but is missing required related entities or fields the UI expects (spaces, property type, address, owner account, etc.), so the web app errors out while rendering the listing page.[1][2]

### Quick sanity checks

Run these against one of the problematic listing IDs:

1. Confirm the listing really exists  
   - `GET /v1/listings/{id}` and verify you get a full JSON object, not a 404/500.[1]
   - Compare its shape against a healthy listing you created manually in the UI.

2. Check required related objects  
   For that same `{id}`, call the key sub-resources Guesty expects to exist:[2]
   - `GET /v1/listings/{id}/spaces` – at least one “space” (bedroom, entire place, etc.)  
   - `GET /v1/listings/{id}/house-rules`  
   - `GET /v1/listings/{id}/availability-settings`  
   - If you are using complexes/multi-units, verify the complex and parent-child relationships.

3. Validate minimal required fields  
   In the listing payload, make sure at least:  
   - `accountId` / owner mapping is valid.  
   - `type` / property type is a supported value (entire place, private room, etc.).[3]
   - Basic address object or localization fields are non-null if the UI assumes them.

### Common causes when importing via API

- You only called `POST /listings` and did **not** follow up with the recommended create calls (spaces, rules, availability, etc.), leaving the listing in a half-initialized state that the UI cannot render cleanly.[2]
- A field contains an unexpected enum/string (e.g., property type or status), which the UI code does not guard against.  
- The listing is in an internal status (“unlisted”, “archived”, or similar) that is not handled correctly in the front-end path you’re using.[4]
- There is a front-end error (JS exception) caused by missing nested objects; you’ll see this in the browser devtools console.[5]

### How to narrow it down fast

- Open devtools → Network tab while loading the broken listing page.  
  - See which API call returns 500/400 or empty data.  
  - Inspect that response for an error message or missing field hints.[5][1]
- In the Console tab, look for an exception like “Cannot read properties of undefined (…something…)”; that usually points directly to the missing nested object.

### Minimal “safe” creation flow (for future imports)

When you create a listing via Open API, follow Guesty’s recommended sequence for a minimal, UI-safe listing:[2]

1. `POST /listings` – create the shell listing with valid type, account, address.  
2. `POST /listings/{id}/spaces` – at least one primary space.  
3. `PUT /listings/{id}/availability-settings` – basic availability window.[6]
4. Optionally: house rules, booking policies, pricing, etc.
